My Journey with JavaScript and Decolonial Design

February 17, 2025

As I keep building my website based on the K53 driving manual, I’ve started using JavaScript to make it more interactive. Even though I’m still new to the language, I’ve begun setting up features like a fun road sign quiz, hover effects on the menu, and pop-up messages that share useful driving tips or safety facts from South Africa. These features will help make the site more fun to use, more useful, and better suited for local users.

Getting Started with GitHub and GitHub Pages

Using JavaScript has pushed me to think more carefully about how users interact with the site, how they connect with the content and what types of actions feel natural, useful, and suited to local cultures. For example, I’ve had to change how I show information, instead of using Western web styles that might not work well here. Rather than filling the site with flashy content or confusing menus, I’ve kept it simple, clear, and easy on data, because many South African users browse the internet on phones with limited data.

Thinking about decolonisation while working on this has made me see that coding isn’t just about tech, it’s also about power. Every line of code and every action I design comes with hidden ideas. Who am I designing this for? Whose knowledge is being shown on the site? For example, instead of only using global icons or just English, I’m trying out adding isiZulu, isiXhosa, and Sesotho words where it makes sense. This questions the idea that only English (or so-called “universal” signs from the Global North) are good enough for teaching and learning.

I’ve also learned that even the way I write my code should show care and inclusivity. Writing neat, organized code with comments in JavaScript is a small way to make my work easier to understand for future developers, especially people like me from the Global South who might be learning on their own without much help.

When it comes to making my coding more decolonial, this project has reminded me to:

  • • Think twice before using Western design styles that might not fit local cultures. • Focus on making the site easy to use and not heavy on data, to match local internet access.
  • • Choose designs that show and value local knowledge, like using South African driving scenes, symbols, and languages.
  • • Write code in a way that makes it easy for others to learn from or build on for their own projects.

In the end, using JavaScript on my site isn’t just about adding fun tools, it’s about using interactivity to show care, include everyone, and reflect local meaning. As someone learning and creating in the Global South, I’m starting to see myself not just as a coder, but also as a storyteller and culture worker who can use tech to push back against systems that leave people out.
